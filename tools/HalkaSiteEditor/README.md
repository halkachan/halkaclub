# HALKA SITE EDITOR v1.3

halkaclub.com の中身を、HTMLを直接さわらずに書き換えるWindows専用アプリです。.NET 8 / WPF。

HTMLの構造は変えません。**値が入っている1か所だけ**を差し替えるので、前後の書き方・インデント・改行コードは元のまま残ります。

## できること

| タブ | 直せるもの | 書き込まれるファイル |
| --- | --- | --- |
| 依頼ページ | 受付状況、7項目の料金、**追加プラン8項目の名前と金額**。**日本語版と英語版がとなり合わせ**で並びます | `commission/index.html`、`commission/en/index.html` |
| ページの文章 | 依頼ページ（日英）と**うたまぜ！のページ**の、説明文・見出し・箇条書き・注意書き・テンプレート | 同上、`utamaze/index.html` |
| 作品一覧 | **分類**と作品の**追加・並べ替え・削除**、タイトル／投稿日／URL。**YouTubeの新着から選んで足せます** | `works/works-data.js` |
| うれしいこと | トップページのお知らせを**追加・並べ替え・削除**。日付／見出し／説明／受賞 | `index.html` |
| ゲーム | ゲーム集のカードの**追加・並べ替え・削除**と、各ゲームの名前・URL・版・**更新履歴** | `game/index.html`、`game/<名前>/index.html` |
| リンク | トップページの大きいリンク4枚と、**リンク集の追加・並べ替え・削除** | `index.html` |
| トップページ | 最新動画のURL（サムネイルがその場で出ます）、「うれしいこと」の年 | `script.js`、`index.html` |
| はるかくらぶ | 最新更新の**日付と内容**、Koofr の入口URL | `club/index.html` |
| うたまぜ！ | 公開済みかどうか、最新の版、各URL。**リリース手順6項目の切り替え** | `utamaze/version.json`、`utamaze/index.html`、`index.html` |
| ページの顔 | 全ページの**ページ名・検索結果の説明・SNSカードの文章**と、**カード画像の差し替え** | 各ページの `<head>`、`assets/ogp/` |
| サイトの基本色 | 紙の白・外側の灰色・文字の黒・黄色・うすい文字・赤い縦線 | `style.css` |

「ゲーム」「はるかくらぶ」「うたまぜ！」は、そのページがサイトに無ければタブごと出ません。

料金の行にある「英語を合わせる」を押すと、日本語側の数字から `from 〇〇 JPY` を作って英語側へ入れます。英語版だけ直し忘れる事故を防ぐためのものです。

**ページの文章**は、HTMLの印が出てこない形で編集します。**空行で区切ると別の項目**（箇条書きの別の行、別の段落）になり、項目の中で改行すると表示でもそこで改行されます。ページごとに段落の作りが違うため、組にはせずページを選んで直します（選ぶと右のプレビューもそのページへ移ります）。

**うたまぜ！のページ**も同じ仕組みで直せます（46か所）。見出し・小見出し・FAQの質問と答え・注意書きまで含み、項目の名前は「FEATURES：見出し」「かんたん：説明」「FAQ：PROは何台のPCで使えますか？」のように、近い見出しから作ります。**リンクが入っている文章と、「※ 現在は公開準備中です。」は、ここには出てきません**（前者はHTMLの印が消えてしまうため、後者は「うたまぜ！」タブのリリース手順が受け持つため）。改行の印は、依頼ページが `<br />`、うたまぜ！のページが `<br>` と、それぞれのページの書き方のまま戻します。

元の体裁（1行で書かれた段落か、複数行に分けて書かれた段落か）は項目ごとに覚えていて、**触っていない所は1文字も変わりません**。これはテストで固定してあります。

**うれしいこと**は受賞やイベント参加のお知らせです。説明と受賞欄は空のままにできて、空ならその行ごとHTMLから消えます（余計な空タグを残しません）。受賞は1行＝1つです。

**作品一覧**には「最近の動画から選ぶ」があります。YouTubeの新着（最新15本）を取ってきて、**まだ入っていないものだけ**を選んで足せます。タイトル・投稿日・URLは自動で入るので、あとから直すだけです。APIキーは要りません（公開されているRSSを読んでいます）。チャンネルIDはその画面で変えられ、覚えておきます。

**ゲーム**は「編集するもの」で、ゲーム集（一覧ページ）か、ゲーム1本を選んで直します。選ぶと右のプレビューもそのページへ移ります。

一覧ページでは、カードの**追加・並べ替え・削除**と、名前・説明・札（「スマホ対応」など1行＝1つ）・ゲームページの場所を直せます。**左上の番号（01、02…）は並び順から自動で振り直します。**

ゲーム1本のページでは、名前・ゲーム本体のURL・画面の向きの一文・いまの版と、説明・更新履歴を直せます。**名前を変えると、そのページの中の4か所（見出し・ページ名・ヘッダー・起動ボタン）がまとめて変わります。** ゲーム本体のURLも、「ゲームを起動」と「別タブで遊ぶ」の両方に入ります。一覧ページのカードの名前は別なので、必要なら一覧側でも直してください。

**更新履歴**は新しいものが上です。「新しい版を追加」で一番上に足し、版は前の版から1つ進めた形（`ver 1.2` → `ver 1.3`）を入れておきます。内容は1行＝1つで、**`**ここ**` と書くと太字**になります。補足は空のままにでき、空ならその行ごとHTMLから消えます。日付は `2026-09-10` の形で入れると、ページには `2026.9.10` の形で出ます。

版は、更新履歴の一番上・ゲームページの表記・一覧ページの札の3か所に出てきます。食い違っていると「更新履歴」の横にその旨が出て、**「版をそろえる」**で3か所そろえられます。更新したのに一覧の札が古いまま、を防ぐためのものです。

転送だけのページ（`game/mine-dungeon/` のような置き石）は、ゲームのページではないので一覧にも編集にも出てきません。

**作品一覧**は分類を選んでから編集します。`↑` `↓` で並べ替え、`✕` で一覧から外し、「この分類に作品を追加」で一番下に足します。投稿日は `2026-01-23` の形、URLはサイト側と同じ判定なので、サムネイルが出ないURLは弾かれます。

**分類そのもの**（「ひらがな一文字シリーズ」など）も、「分類を追加」で増やせます。上の箱で名前・説明を直し、`↑` `↓` `✕` で並べ替えと削除ができます（削除は中の作品ごとです）。**合い言葉**はページが分類を見分けるための名前で、英小文字・数字・ハイフンだけ、重なりは弾きます。作ったあとは変えないほうが安全です。作品一覧ページは `works-data.js` だけを見ているので、分類を足してもHTMLの作業はありません。ファイル先頭の説明コメントには触れません。

**リンク**タブは2段です。上の**大きいリンク**（作品一覧・インスト置き場・依頼・はるかくらぶ）は置き場所が決まっているので、名前・説明・リンク先だけを直します。下の**リンク集**は `↑` `↓` `✕` と「リンクを追加」で増減できます。1枚ごとに、印（左の四角に出る1〜2文字）・名前・説明・リンク先・読み上げ・「大きく出す」を直せます。**リンク先が `http` で始まればよそのサイト**として別タブで開く形になり、そうでなければサイトの中として扱います。うたまぜ！のリンクは「うたまぜ！」タブが受け持つので、ここには出てきません。

## ページの顔（v1.0）

**ページの顔**タブで、ページを選んで直します。選ぶと右のプレビューもそのページへ移ります。

| 欄 | どこに出るか |
| --- | --- |
| ページ名 | ブラウザのタブと、検索結果の見出し |
| 検索結果の説明 | 検索結果で、見出しの下に出る文章 |
| カードの見出し | XやDiscordにURLを貼ったときの太字 |
| カードの説明 | その下に出る文章 |
| 画像の説明 | 画像が出ないときに代わりに読まれる文字 |

書いていない欄は、そのページには出しません（「はるかくらぶ」には検索結果の説明がないので、欄も出ません）。

**カード画像**は 1200×630 のPNGです。「画像を選ぶ...」で差し替えられ、**形と大きさが合わないものは受け取りません**。「保存する」を押すまで、ファイルは入れ替わりません。

**「カード画像を作り直す」**は、`tools/ogp/generate-ogp.py` を動かして8枚をまとめて作り直します（Python と Pillow・fontTools・brotli が要ります。足りないときは入れ方を出します）。**絵柄と画像の中の文字は、このスクリプトの中の一覧で決まっていて、上で直すOGPの文章とは別物です。**

**トップページ**タブでは、ﾊﾙｶﾁｬﾝのGIFを差し替えられます。`index.html` と `script.js` の2か所から読まれているので、**両方の `?v=` を自動で上げます**（上げないと、見る人のブラウザが古い絵をしばらく掴んだままになります）。

**「sitemap を作り直す」**は、いまサイトにあるページから `sitemap.xml` と `robots.txt` を書き直します。`noindex` のページと、よそへ飛ばすだけのページは入れません。うたまぜ！を公開の形にすると、次に押したときから載るようになります。ドメインは `CNAME` から読みます。

## プレビュー（v0.2）

右側に、実際のサイトがそのまま出ます。**保存するとこの表示も作り直されます。**

- **PC** と **スマホ（375px）** を並べて確認できます。「表示」で片方だけにもできます。PCのみにすると大きく出るので、文字を読むときはこちらが見やすいです
- PC側は横1280px相当の画面を縮めて出しています。見出しの横に出ている％が縮小率です
- 「ページ」で、トップ・依頼ページ・作品一覧など、サイトにあるページを切り替えられます。**編集タブを切り替えると、関係するページへ自動で移ります**
- 上の「プレビュー」のチェックを外すと、プレビューごと隠して編集画面を広く使えます

`file://` で開くと `/favicon.png` のような絶対パスが外れて本番と見え方が変わるため、アプリの中に小さなHTTPサーバー（`127.0.0.1` のみ・ランダムな番号）を持たせて、本番と同じ形で出しています。サイトのフォルダーの外は配りません。

表示には **WebView2 ランタイム**が必要です（Windows 11 なら通常は入っています）。入っていない場合は、プレビュー欄にその旨を出します。編集と保存はプレビューが無くても使えます。

## 使いかた

1. `dist/win-x64/HALKA SITE EDITOR.exe` を起動します。EXEの近くにある halkaclub フォルダーを自動で探します。見つからないときは「フォルダーを選ぶ...」で指定してください（一度指定すると次回から覚えます）。
2. 直したい値を書き換えます。変えた欄は枠が黄色くなり、下の **変更一覧** に「変更前 → 変更後」が並びます。
3. 「保存する」でファイルに書き込みます。確認のダイアログが出ます。
4. 右のプレビューが作り直されるので、そこで確かめます。
5. 問題なければ「公開する」を押します。GitHub Desktop を使っても構いません。

## 取り消しと、やり直し（v1.3）

変更一覧の上に、4つのボタンがあります。

- **元に戻す** — 追加・並べ替え・削除・「版をそろえる」「まとめて公開の形にする」「英語を合わせる」を、**1手ずつ**戻します。ボタンの上にカーソルを置くと、次に何が戻るか出ます。**文字の打ち直しは入力欄の中で Ctrl+Z** です（こちらはWindowsのしくみなので、ここには出てきません）。保存すると、覚えていた手は忘れます
- **すべて元に戻す** — 読み込んだときの状態まで、まとめて戻します
- **保存を1つ前に戻す** — 保存するたびに、**書き換わるファイルの控え**を自動で取っています。押すと、いちばん新しい控えを書き戻して読み込み直します。控えは `%LOCALAPPDATA%\HalkaSiteEditor\backup` に、**サイトのフォルダーごとに分けて**新しいものから10回分まで残します（別のフォルダーの控えを間違って書き戻さないためです）。サイトのフォルダーの外なので、公開には混ざりません
- **サイトを開く** — halkaclub.com をブラウザーで開きます。公開したあとの確認に使います

上の **近道を作る** で、デスクトップとスタートメニューにこのアプリの近道（ショートカット)を作れます。

## 公開する（v0.4）

右下の「公開する（n）」で、保存した内容を halkaclub.com へ出します。n は公開を待っているファイルの数です。

押すと確認の画面が出ます。**送り先のブランチ・公開されるファイルの一覧・記録に残す説明**を見てから、もう一度「公開する」で確定します。説明は変わったファイルから自動で下書きされます（例：`依頼ページ・作品一覧を更新`）。

- **このツールが扱うファイルだけを公開します。** 同じリポジトリの `unity-project/` などで作業中の変更は、巻き込まれず手元に残ります
- **保存していない変更があるうちは押せません。** 先に「保存する」を押してください
- **別の場所から先に変更が入っていた場合**（GitHub Desktop や別のPCから push したあとなど）は、押し返されたことを知らせて「取り込んでから公開しますか？」と聞きます。はいを選ぶと、作業中のファイルをいったん避けて取り込み、自動で戻してから公開し直します
- うまくいかなかったときは、手元のファイルはそのままです。内容を出すので、GitHub Desktop から確かめてください

公開してから halkaclub.com に出るまで、30秒ほどかかります。

## うたまぜ！のリリース（v0.6）

正式リリースのときに必要な場所を、**6項目まとめて一覧**にしてあります。どれか1つだけ変えて気づかない、を防ぐためのものです。

1. 検索に載せる（`noindex` を外す）
2. 上のダウンロードボタン
3. FREEのダウンロードボタン
4. PROの購入ボタン（購入URLはここ1か所だけ）
5. 「公開準備中です」の一文を消す
6. トップページにリンクを出す

各項目には**いまの状態（準備中／公開／不明）**が出ます。「まとめて公開の形にする」で全部そろえられ、**準備中へ戻すこともできます**。ダウンロードURLは `version.json` の値を初期値にします。購入URLが空のままPROのボタンを公開にしようとすると、誤りとして止まります。

トップページのリンクは、`index.html` に置いた `<!-- utamaze-link:start -->` と `<!-- utamaze-link:end -->` の間に出し入れします。**出し入れするとリンクの数が変わるため、保存のあと自動で読み込み直します。**

一部だけ公開された状態で「公開する」を押すと、確認が出ます。

ページを手で書き換えていて、準備中とも公開とも読み取れないときは **「不明」** と出て、そこだけ切り替えできなくなります（勝手に直しません）。
## 安全のための決まり

- **改行コードを変えません。** このリポジトリは `index.html` が CRLF、`style.css` が LF というように混在しています。値の前後に触れないので、差分は変えた行だけになります。
- **書き込みは一時ファイル経由**です。途中で落ちても元のファイルが壊れません。
- **保存の直前に控えを取ります。** 「保存を1つ前に戻す」で、書き込む前の中身へ戻せます。
- **画像を入れ替えるのは、文章の書き込みが全部すんだあと**です。差し替えをやめれば、元の画像のままです。
- **読み込んだあとに別の場所でファイルが変わっていたら、保存を中止します。** VS Code で同じファイルを開いて直していたときに、片方の変更が消えるのを防ぐためです。読み込み直してからやり直してください。
- 入力に誤りがあると「保存する」が押せません。色は書き方（`#ffdc18` など）、動画URLはサイト側の `extractYouTubeId` と同じ判定、HTMLに入る文字は `< > &` を弾きます（ゲームの更新履歴だけは `**ここ**` の強調を通します）。
- 依頼ページの項目数が日本語版と英語版で食い違っていると、読み込み時に止まります。先にHTMLを揃えてください。

## 開発とテスト

```
dotnet build HalkaSiteEditor.sln -c Release
dotnet run --project HalkaSiteEditor.Tests -c Release
```

テストは本物のリポジトリを**読むだけ**で、書き込みの確認は毎回つくる一時フォルダーのコピーに対して行います。改行コードが変わらないこと、触っていないファイルが1バイトも変わらないこと、横から書き換えられていたら保存を中止すること、プレビュー用サーバーがフォルダーの外を配らないことまで見ています。

配布用のEXEは PowerShell で `./scripts/publish-win-x64.ps1` を実行すると `dist/win-x64/` に出ます。自己完結版なので、.NETが入っていないPCでも動きます。

落ちたときの内容は `%LOCALAPPDATA%\HalkaSiteEditor\crash.log` に残ります。

アプリアイコンは `HalkaSiteEditor/Assets/site-editor.ico`。変えるときは Pillow 入りの Python で `py scripts/generate-app-icon.py` を実行します。

この PC には .NET 8 ランタイムが無く 10 だけなので、`HalkaSiteEditor.csproj` に `<RollForward>Major</RollForward>` を入れてあります。`dotnet build` しただけのEXEも、これで起動します。

## 扱わないこと

ページの追加や並べ替え、レイアウトそのものの変更は扱いません。HTMLの構造を変える作業は、今までどおり VS Code で行ってください（[ルートのREADME](../../README.md)）。
