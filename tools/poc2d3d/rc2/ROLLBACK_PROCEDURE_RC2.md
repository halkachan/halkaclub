# はるかわーるど ver3.0 ロールバック手順書（ver2.9 に戻す）

ver3.0 の公開後に重大な問題が見つかったとき、公開中のゲームを ver2.9 に戻す手順です。**公開や戻す作業は、ユーザーの承認の後にだけ行います。**

## セーブデータはどうなるか（テスト環境で確認済み）

| データ | ver2.9 に戻したとき | もう一度 ver3.0 にしたとき |
|---|---|---|
| 歩いた数・プレイ時間（`HALKA_WORLD_life_log_v1`） | ver3.0 が毎回同じ値を書いているので、ver2.9 がそのまま読む。ver2.9 で遊んだ分も増える | ver2.9 で増えた歩数・時間を取り込む（旧キーの方が進んでいれば、そちらを使う） |
| 朝夜（`HALKA_WORLD_time_cycle_anchor_v1`） | ver2.9 は使わない（キーは残る） | そのまま読む |
| 新しいセーブ（`harukaworld_save/` のファイル） | ver2.9 は触らない。消えない | 最後にいた場所・表示・AUTO から続く |

**IndexedDB やブラウザのデータを消す必要はありません。ユーザーにお願いしてもいけません。**

Phase 6 での確認（`127.0.0.1:8898/halkaworld/webgl/` のテスト用オリジン、テスト用のプロファイル）:

1. ver2.9 で遊ぶ → `v1|5|29`
2. RC2 → 5歩・29秒を引き継ぐ → 遊ぶ → `v1|22|54`
3. ver2.9 に戻す → `v1|22|54` が表示される。遊ぶ → `v1|25|83`。新しいセーブのファイルは5つとも残っている
4. RC2 に戻す → 25歩・83秒、家の中の最後の場所から続いた

## 手順

1. 戻す前に、`origin/main` の状態を記録する（`git log -1 origin/main`）。
2. `halkaworld/webgl/` を、ver2.9 の Build（ver3.0 公開の直前のコミットの `halkaworld/webgl/`）に戻すコミットを作る。
   - **`git revert` で戻す。** 履歴を消す `reset` や `force push` はしない。
   - 別件の更新（みねはうす など）は戻さない。
3. `halkaworld/index.html` も ver2.9 の表示（`ver2.9`、iframe の `?v=2.9&build=...`）に戻す。
4. ユーザーの承認を得て push し、GitHub Pages の更新を待つ。
5. 確認する。
   - ver2.9 が開く
   - 以前のブラウザで、歩いた数・プレイ時間が残っている
6. 問題を直した ver3.0 をもう一度公開するときは、`PUBLISH_PROCEDURE_RC2.md` をやり直す。新しいセーブのファイルは残っているので、続きから遊べる。

## してはいけないこと

- IndexedDB の全消去、サイトデータ削除の案内
- 保存キー（`HALKA_WORLD_life_log_v1`、`HALKA_WORLD_time_cycle_anchor_v1`）の名前の変更や削除
- ゲームのパス `/halkaworld/webgl/` の変更
- main の履歴の書き換え（force push）
