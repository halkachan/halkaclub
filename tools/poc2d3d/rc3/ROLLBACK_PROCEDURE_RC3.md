# はるかわーるど ver3.0 ロールバック手順書（ver2.9 に戻す）

ver3.0 の公開後に重大な問題が見つかったとき、公開中のゲームを ver2.9 に戻す手順です。

**公開や戻す作業は、ユーザーの承認の後にだけ行います。**

## セーブデータはどうなるか（テスト環境で確認済み）

| データ | ver2.9 に戻したとき | もう一度 ver3.0 にしたとき |
|---|---|---|
| 歩いた数・プレイ時間（`HALKA_WORLD_life_log_v1`） | ver3.0 が毎回同じ値を書いているので、ver2.9 がそのまま読む。ver2.9 で遊んだ分も増える | ver2.9 で増えた歩数・時間を取り込む（旧キーの方が進んでいれば、そちらを使う） |
| 朝夜（`HALKA_WORLD_time_cycle_anchor_v1`） | ver2.9 は使わない（キーは残る） | そのまま読む |
| 新しいセーブ（`harukaworld_save/` のファイル、3世代と控え） | ver2.9 は触らない。消えない | 最後にいた場所・表示・AUTO から続く |
| エクスポートしたファイル | 端末に残る（ゲームは触らない） | インポートで使える |
| ほかのページのデータ（みねはうす など） | 触らない | 触らない |

**IndexedDB やブラウザのデータを消す必要はありません。ユーザーにお願いしてもいけません。**

### Phase 7 での確認

条件: 本番と同じ「同じオリジン・同じパス」を再現したテスト用サイト `http://127.0.0.1:8901/`。ver2.9 の公開ツリーと統合リハーサルのツリーを、同じオリジンで切り替えた。テスト用の Chrome プロファイルを使った。

| 手順 | 結果 |
|---|---|
| 1. ver2.9 で5歩 | `v1\|5\|29` |
| 2. ver3.0 を公開した状態にして、遊ぶ（家の中・3D、エクスポート・インポート） | 20歩、旧キー `v1\|20\|52` も同時に書かれる |
| 3. ver2.9 に戻した状態にする（ページと Build を ver2.9 に。ver3.0 の Build ファイルは残す） | ver2.9 が 20歩を読み、遊ぶと `v1\|23\|81`。新しいセーブのファイル5つは残っている |
| 4. もう一度 ver3.0 を公開した状態にする | 23歩・81秒、家の中の最後の場所から続く |

詳しくは Phase 7 レポート 23章にあります。

## 手順

1. 戻す前に、`origin/main` の状態を記録する（`git log -1 origin/main`）。
2. ver3.0 を公開したコミット（`halkaworld/index.html`、`halkaworld/game-page.css`、`halkaworld/webgl/`）を **`git revert` で戻す**。ただし、**ver3.0 の Build ファイル（4つ）は消さずに残す**。
   ```
   git revert --no-commit <公開したコミット>
   git checkout <公開したコミット> -- halkaworld/webgl/Build/<ver3.0 の4ファイル>
   git commit
   ```
   - 理由: 戻した直後の最大10分は、ver3.0 のページをキャッシュしているブラウザが、ver3.0 のゲームを読み込みます。そのファイルが消えていると、ゲームが「Unknown data format」で始まりません（Phase 7 で確かめた。セーブは壊れない）。
   - ver3.0 の Build ファイルは、1日以上たってから別のコミットで消す。
   - 履歴を消す `reset` や force push はしない。
   - 公開のときに一緒に merge した ver3.0 のソース（`unity-project/` など）は、戻さなくても公開ページに影響しない。戻すのは公開されるファイルだけでよい。
   - 別件の更新（みねはうす、トップページ など）は戻さない。revert の差分に、`halkaworld/` 以外が入っていないことを確かめる。
   - トップページのﾊﾙｶﾁｬﾝの GIF を新しい絵に替えていても（別のコミット）、ゲームとは関係しないので、ここでは戻さない。
3. 戻した結果、次の状態になっていることを確かめる。
   - `halkaworld/index.html` が ver2.9（`ver2.9`、iframe の `?v=2.9&build=a5659b8e…`）
   - `halkaworld/webgl/index.html` が ver2.9 のもの、`halkaworld/webgl/Build/` に ver2.9 の4ファイル（と、残した ver3.0 の4ファイル）
4. ユーザーの承認を得て push し、GitHub Pages の更新を待つ。
5. 確認する。
   - ver2.9 が開く
   - 以前のブラウザで、歩いた数・プレイ時間が残っている
   - ほかのページが変わっていない
6. 直した ver3.0 をもう一度公開するときは、`PUBLISH_PROCEDURE_RC3.md` をやり直す。新しいセーブのファイルは残っているので、続きから遊べる。

キャッシュについて:

- GitHub Pages のファイルは約10分キャッシュされます。
- ゲームのファイルは名前に中身の識別子が入っているので、古いものと新しいものが混ざって動くことはありません。
- 戻した直後に古い（ver3.0 の）ページが見えることがあります。ver3.0 の Build ファイルを残しておけば、そのページのゲームも動きます。その間に遊んでもセーブは壊れません（ver3.0 は旧キーも書き続ける）。

## してはいけないこと

- IndexedDB の全消去、サイトデータ削除の案内
- 保存キー（`HALKA_WORLD_life_log_v1`、`HALKA_WORLD_time_cycle_anchor_v1`）の名前の変更や削除
- ゲームのパス `/halkaworld/webgl/` の変更
- main の履歴の書き換え（`reset --hard`、force push）
- ほかのページ（みねはうす など）の巻き戻し
